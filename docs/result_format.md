# 결과 형식 문서 (다른 팀용 인터페이스)

> **상태: 상시 서비스와 MQTT 발행은 미수행입니다.** 아래는 각 앱을 켰을 때 실제로 있는 **HTTP 조회 주소**만 적은 것입니다. 앱이 꺼져 있으면 조회할 수 없고, 12시간 가동이나 MQTT 토픽은 없습니다.
> 아래 JSON 예시의 숫자는 형식을 보여 주는 예시이고(일부는 보고서 값), 측정 기록이 아닙니다.
> 모든 응답은 JSON, 시각(`ts`)은 유닉스 초(UTC 기준 epoch), 거리 단위는 m입니다. 영상(`/stream`)은 사람이 보는 용도이고 다른 팀이 가져다 쓰는 데이터가 아닙니다.

## 1. 물체 검색 — `08_webcam_object_search/app.py` (포트 8001)

| 주소 | 내용 | 갱신 |
| --- | --- | --- |
| `GET /recent?n=12` | 최근 추출 물체 n개와 상태 | 크롭이 생길 때마다(배치 2) |
| `GET /search?q=<글>&k=12` | 글과 가장 비슷한 물체 k개 | 요청할 때 계산 |

`/recent` 응답:

```json
{
  "mode": "relabel",
  "stats": {"fps": 12.4, "embed_ms": 677, "avail_mb": 1800, "min_avail_mb": 1239},
  "total": 25,
  "items": [{"id": 17, "label": "건전지", "lscore": 0.757, "cls": "book", "conf": 0.41, "ts": 1761206100.0, "img": "/crops/..."}]
}
```

| 필드 | 뜻 |
| --- | --- |
| `label`, `lscore` | 최종 이름과 그 이름 문장과의 유사도 (relabel/yoloe) |
| `cls`, `conf` | YOLO 검출기 원래 이름과 신뢰도 |
| `score` | (`/search`만) 검색어와의 유사도 |
| `img` | 크롭 이미지 경로 (운영 모드라면 꺼야 하는 경로, 확인 문제 6-4) |

## 2. 동작·행동 — `09_pose_action/pose_app.py` (포트 8001)

| 주소 | 내용 | 갱신 |
| --- | --- | --- |
| `GET /events` | 동작 횟수, 최근 이벤트 20개, 행동 패턴 집계, 지금 보이는 사람 상태 | 프레임마다 (웹 화면은 1초마다 읽음) |

```json
{
  "mode": "smooth +behavior +model",
  "stats": {"fps": 15.2, "people": 1, "avail_mb": 2900, "min_avail_mb": 2644},
  "counts": {"만세": 7, "한팔들기": 7, "손흔들기": 5},
  "events": [{"ts": 1761440000.0, "who": "#2", "label": "손흔들기"}],
  "beh": {"지나감": 5, "힐끗 봄": 8, "관심 있음": 3},
  "interest_rate": 0.19,
  "now": {"#2": "한팔들기 / 관심 있음"}
}
```

- `counts`는 앱이 켜진 뒤 누적, `events`는 최근 20개만 (그보다 오래된 것은 사라짐).
- `beh`는 사람 단위(추적 ID 단위)라 ID가 쪼개지면 부풂(확인 문제 4-5).

## 3. 접근 감지 — `10_two_camera_proximity/proximity_app.py` (원문 코드, 포트 8000)

| 주소 | 내용 | 갱신 |
| --- | --- | --- |
| `GET /state` | 타겟 위치, 사람별 거리·추세·구역·TTC, 최근 이벤트 25개 | 프레임마다 (웹 화면은 0.5초마다 읽음) |
| `POST /retarget` | 타겟 다시 찾기 | — |

주요 필드:

| 필드 | 뜻 | 단위 |
| --- | --- | --- |
| `target.xyz` | 타겟 방 좌표 (x, y, z) | m |
| `target.how` | 찾은 방법 ("삼각측량 (재투영 …px)" / "camN 단독 추정" / "직접 지정") | — |
| `people[].id` | 추적 ID | — |
| `people[].d` | 타겟까지 거리 | m |
| `people[].x`, `people[].y`, `people[].h` | 방 좌표 바닥 위치와 어깨 높이 | m |
| `people[].trend` | "접근 중" / "멀어지는 중" / "정지" (최근 1초 거리 변화) | — |
| `people[].zone` | `near`(1.0m 안) / `mid` / `far`(3.0m 밖) | — |
| `people[].closing`, `people[].ttc` | 접근 속도, 충돌 예상 시간 (`--moving`) | m/s, 초 |
| `people[].kind` | `stereo`(두 카메라 삼각측량) / `single`(한 카메라 추정, 오차 큼) | — |
| `people[].pose` | "섬" / "앉음" (어깨 1.15m 기준, `stereo`일 때만, 아니면 "-") | — |
| `people[].danger` | 충돌 위험 알람 켜짐 (`--moving`) | — |
| `near`, `far` | 알람 거리 설정 | m |
| `events[]` | `{ts, who, label}`. 알람은 `label`이 "알람: 근접 …", "알람: 이탈 …", "알람: 충돌 위험 …" | — |

- 알람은 상태가 바뀔 때만 이벤트로 남는다(경계에서 0.2m 히스테리시스).
- `kind: single`인 값은 카메라 높이에 따라 1m 넘게 틀릴 수 있다(우리 측정 1.26m). 제어에 쓸 때는 `stereo`만 믿는 것을 권한다.

## 하지 않은 것

- MQTT 토픽, retain, 발행 주기: **미구현.** 같은 보드의 공기 측정 대시보드와는 MQTT로만 잇기로 계획했지만 이 실습 기간에는 만들지 않았다.
- 결과에 "값이 얼마나 오래됐나(age)", "얼마나 믿을 만한가(신뢰도)" 필드를 따로 두지 않았다(`/state`의 `kind`가 그 역할을 일부 함).
