# 7단계 도메인 미세조정 (강의실 질의-문서 쌍으로 텍스트 모델 추가 학습)

> 원문: 실습 README의 "7단계 도메인 미세 조정"
> 앞 단계: [03-text-search.md](03-text-search.md) 통과, [06-performance.md](06-performance.md) 통과

## 0. 이 단계에서 무엇을 하나

3단계에서 모델이 "졸려요 → CO2 문장"처럼 뜻으로 찾는 걸 봤다. 7단계는 **강의실 분야의 질문-답 쌍을 더 보여 줘서** 이 분야 검색을 더 잘하게 만드는 것이다.

- **학습 데이터**(`train.jsonl`, 282쌍): "질문 하나 + 정답 문서 하나"가 한 줄. 모델은 같은 배치 안의 다른 문서를 오답으로 삼아 "정답은 가깝게, 오답은 멀게" 배운다(MultipleNegativesRankingLoss).
- **평가 데이터**(`eval.jsonl`, 60쌍 = 문서 20개 × 질의 3개): 학습에 한 번도 안 쓴 문서와 질문이다. 학습 전 모델과 학습 후 모델을 **같은 시험지**로 재서 비교한다.
- 점수 뜻
  - **accuracy@1**: 질문 60개 중 정답 문서를 **1위**로 찾은 비율
  - **accuracy@3**: 정답이 **3위 안**에 든 비율
  - **ndcg@10**: 정답이 10위 안에서 **얼마나 위에** 있는지 (1이면 모두 1위)
- **MatryoshkaLoss**로 감싸서 학습하므로 학습 뒤에도 512·256·128차원으로 잘라 쓸 수 있어야 한다.

## 1. 성공 기준 (먼저 적어 둔다)

원문에는 합격선 숫자가 없고 "학습 전후 비교"와 확인 포인트만 있다. 그래서 아래처럼 정한다. **결과를 본 뒤 기준·설정을 바꾸지 않는다.**

| # | 기준 | 통과 조건 |
| --- | --- | --- |
| 1 | 도메인 검색이 좋아졌다 | `eval.jsonl` 768차원에서 미세조정 모델의 **accuracy@1과 ndcg@10이 둘 다 기준 모델보다 높다** |
| 2 | 일반 검색이 무너지지 않았다 (원문 확인 포인트) | 미세조정 모델로 3단계 `test_text.py`를 돌려 **6칸 모두 PASS** (기준 모델은 맥에서도 6칸 PASS) |
| 3 | 학습이 끝까지 돌았다 | `models/eg2-classroom`이 저장되고 `eval_ir.py`로 다시 불러 잴 수 있다 |

세 가지 다 만족하면 **통과**. 하나라도 아니면 **미통과**로 적고 이유를 쓴다.

참고로만 볼 것(통과 조건 아님): 512·256·128차원 점수, accuracy@3·@5, 학습 시간, 맥 메모리.

**지키는 것:**

- 학습 설정은 **원문 그대로** 한 번만 돌린다: epoch 3, 배치 8 × 누적 2, lr 2e-5, warmup 0.1, bf16, MatryoshkaLoss(768/512/256/128).
- `eval.jsonl`은 **재기만** 한다. 학습 중 epoch마다 찍히는 eval 점수(원문 코드)는 지켜보기만 하고, 그걸 보고 epoch·lr을 고르거나 "가장 좋은 epoch"를 고르지 않는다. **마지막 epoch 모델**을 쓴다.
- 원문 확인 포인트의 "점수가 떨어지면 epoch를 줄이거나 lr을 낮춘다"는 `eval.jsonl`로 설정을 고르는 일이 되므로 이번에는 하지 않는다. 떨어지면 미통과로 적고, 고칠 방법은 "다음에 할 일"에만 쓴다.

## 2. 원문과 이렇게 다르게 한다

| 원문 | 우리 | 이유 |
| --- | --- | --- |
| Jetson(`device="cuda"`)에서 학습 | **맥**에서 학습. 장치는 자동 선택(맥은 `mps`, 보드는 `cuda`) | 팀 규칙 6번: 보드 학습 금지(보드 B가 두 번 멈춤) |
| `~/eg2`(보드 venv) | 맥 `~/eg2-mac` (Python 3.12, torch 2.14.1, transformers 5.20.2, sentence-transformers 6.2.0, datasets 5.1.0) | 맥 전용 환경. 공기 측정 프로젝트 폴더·venv는 건드리지 않는다 |
| `nohup python train_ft.py &` | `caffeinate -i`를 붙여 실행 | 맥이 잠들면 학습이 멈춘다. 뚜껑은 열어 두고 충전기를 꽂아 둔다 |
| 끊기면 처음부터 | epoch마다 `runs/eg2-classroom/checkpoint-*` 저장, 다시 실행하면 이어서 함 | 맥을 덮거나 끊겨도 처음부터 안 하게 |
| `eval_ir.py`는 768차원만 | 768/512/256/128 네 차원을 다 재고 `--out`으로 JSON 저장 | Matryoshka 절단이 유지되는지도 같이 본다 |
| 3단계 재확인은 보드 | 맥에서 `EG2_MODEL=models/eg2-classroom python test_text.py` | 같은 모델 파일이라 결과는 같다. 보드에 옮겨 쓰는 일은 8단계부터 원본을 쓰므로 하지 않는다(원문 단계표: "이미지 검색에는 쓸 수 없어 8단계부터는 원본 모델") |

- 모델(`models/`), 체크포인트(`runs/`), 데이터(`data/`)는 커밋하지 않는다(`.gitignore`).
- `eg2.py`는 환경 변수 `EG2_MODEL`이 있으면 그 모델을 쓴다. 없으면 지금처럼 `google/embeddinggemma-2`라서 보드 동작은 바뀌지 않는다. `test_text.py`의 `torch.cuda.*` 줄은 cuda가 있을 때만 돈다(보드에서는 그대로).

## 3. 맥에서 할 순서

```bash
cd ~/work/AIGJ_01_012_embedding_gemma2
source ~/eg2-mac/bin/activate
export HF_HUB_OFFLINE=1
wc -l data/train.jsonl data/eval.jsonl          # 282, 60

python eval_ir.py --out runs/eval-base.json                         # 1) 기준 모델
caffeinate -i python train_ft.py 2>&1 | tee runs/train.log          # 2) 학습 (뚜껑 열어 두기)
python eval_ir.py models/eg2-classroom --out runs/eval-ft.json      # 3) 미세조정 모델
EG2_MODEL=models/eg2-classroom python test_text.py                  # 4) 일반 검색 재확인
```

학습이 중간에 멈췄으면 2)를 그대로 다시 실행하면 마지막 체크포인트부터 이어서 한다.

## 4. 준비 확인 (가짜 데이터, 2026-10-23)

진짜 데이터가 오기 전에, 코드가 맥에서 끝까지 도는지와 걸리는 시간을 **가짜 데이터**(지어낸 질문-문서 48쌍, 평가 10쌍)로 확인했다. 이 숫자는 판정에 쓰지 않는다.

| 확인 | 결과 |
| --- | --- |
| 장치 | `mps:0` (M2 GPU), bf16 학습 오류 없음 |
| 학습 9스텝(3 epoch) | 51초, 스텝당 약 4.5초 |
| 맥 메모리 최대 | 약 5.8GB (16GB 중) |
| 저장·다시 불러 평가 | 됨 |
| 맥에서 기준 모델로 3단계 `test_text.py` | 6칸 PASS (보드 A 결과와 같음) |

진짜 데이터는 282쌍이라 epoch당 18스텝, 3 epoch 54스텝이다. 문장이 더 길어 스텝이 조금 느려질 수 있어 **학습은 약 5~10분**으로 본다.

설치 중 겪은 것: 텍스트만 쓰는데도 `pillow`·`torchvision`이 없으면 모델 로드가 `ImportError`로 멈춘다(EmbeddingGemma 2 프로세서가 이미지·동영상 부품을 같이 불러옴). 둘 다 깔아서 해결했다.

## 6. 데이터 (직접 만듦)

원문은 "제공되는 `eval.jsonl` 60쌍, `train.jsonl` 282쌍"이라고 하지만 파일 자체나 받는 곳은 적혀 있지 않다(형식 예시 2줄뿐). 맥·프로젝트 파일·두 저장소의 모든 브랜치를 찾아봤지만 없었다. 그래서 재웅 결정(2026-10-23)으로 **원문 '데이터 준비' 방법대로 Claude가 직접 썼다.** 강사 제공 파일이 나중에 오면 그걸로 다시 하고 두 결과를 같이 적는다.

| | eval.jsonl | train.jsonl |
| --- | --- | --- |
| 규모 (원문 설명과 같게) | 문서 20 × 질의 3 = 60쌍 | 문서 94 × 질의 3 = 282쌍 |
| 다루는 것 (원문 설명과 같게) | 온도·습도·PM2.5·조도·소음·TVOC·재실 인원·냉난방·환기·센서 관리·경보·에이전트 권한 | CO2·환기, 냉난방, 공기질, 센서·네트워크, 경보, 에이전트, 엣지 운영, 과정 운영 |
| 만든 순서 | **먼저** 만들고 해시를 이 보고서에 적어 잠금 | eval 다음에, eval과 같은 사실을 다루지 않게 |
| sha256 | `8649476ea4289a09c7f8c5f211a8eeae8fce54633a00a04892bf91356a48c1cb` | `da16d4487d1d3f5a` (앞 16자리) |

- 수치는 원문처럼 **실습용 가상 운영 기준**이다. 실제 교육장 규정이 아니다.
- 데이터 파일은 커밋하지 않는다(`data/`는 `.gitignore`). 대신 위 해시로 같은 파일인지 확인할 수 있다.
- `check_data.py`로 점검(기준 0.35는 데이터를 보기 전에 정함): train·eval 똑같은 문장 0개, 글자 3개 묶음 겹침 최대 train-eval 문서 0.08, 질의 0.30, 3단계 문장과 0.12 → **겹침 없음**.
- 3단계 `test_text.py`의 문서·질의(CO2 1000ppm·에어컨 26도·조도 300lux)는 학습 데이터에 넣지 않았다. 넣으면 2번 기준(일반 검색 재확인)이 의미 없어진다.
- 한계: 학습·평가 데이터를 **같은 사람(Claude)이 썼다.** 말투·문장 틀이 비슷해서, 남이 만든 평가 데이터보다 점수가 잘 나올 수 있다. 글자 겹침 검사는 같은 뜻을 다른 말로 쓴 경우는 못 잡는다.
