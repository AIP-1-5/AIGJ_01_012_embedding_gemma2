# 7단계 도메인 미세조정 (강의실 질의-문서 쌍으로 텍스트 모델 추가 학습)

## 0. 이 단계에서 무엇을 하나

3단계에서 모델이 "졸려요 → CO2 문장"처럼 뜻으로 찾는 걸 봤다. 7단계는 **강의실 분야의 질문-답 쌍을 더 보여 줘서** 이 분야 검색을 더 잘하게 만드는 것이다.

- **학습 데이터**(`train.jsonl`, 282쌍): "질문 하나 + 정답 문서 하나"가 한 줄. 모델은 같은 배치 안의 다른 문서를 오답으로 삼아 "정답은 가깝게, 오답은 멀게" 배운다(MultipleNegativesRankingLoss).
- **평가 데이터**(`eval.jsonl`, 60쌍 = 문서 20개 × 질의 3개): 학습에 한 번도 안 쓴 문서와 질문이다. 학습 전 모델과 학습 후 모델을 **같은 시험지**로 재서 비교한다.
- 점수 뜻
  - **accuracy@1**: 질문 60개 중 정답 문서를 **1위**로 찾은 비율
  - **accuracy@3**: 정답이 **3위 안**에 든 비율
  - **ndcg@10**: 정답이 10위 안에서 **얼마나 위에** 있는지 (1이면 모두 1위)
- **MatryoshkaLoss**로 감싸서 학습하므로 학습 뒤에도 512·256·128차원으로 잘라 쓸 수 있어야 한다.

## 1. 성공 기준 (먼저 적어 둔다)

원문에는 합격선 숫자가 없고 "학습 전후 비교"와 확인 포인트만 있다. 그래서 아래처럼 정한다. **결과를 본 뒤 기준·설정을 바꾸지 않는다.**

| # | 기준 | 통과 조건 |
| --- | --- | --- |
| 1 | 도메인 검색이 좋아졌다 | `eval.jsonl` 768차원에서 미세조정 모델의 **accuracy@1과 ndcg@10이 둘 다 기준 모델보다 높다** |
| 2 | 일반 검색이 무너지지 않았다 (원문 확인 포인트) | 미세조정 모델로 3단계 `test_text.py`를 돌려 **6칸 모두 PASS** (기준 모델은 맥에서도 6칸 PASS) |
| 3 | 학습이 끝까지 돌았다 | `models/eg2-classroom`이 저장되고 `eval_ir.py`로 다시 불러 잴 수 있다 |

세 가지 다 만족하면 **통과**. 하나라도 아니면 **미통과**로 적고 이유를 쓴다.

참고로만 볼 것(통과 조건 아님): 512·256·128차원 점수, accuracy@3·@5, 학습 시간, 맥 메모리.

**지키는 것:**

- 학습 설정은 **원문 그대로** 한 번만 돌린다: epoch 3, 배치 8 × 누적 2, lr 2e-5, warmup 0.1, bf16, MatryoshkaLoss(768/512/256/128).
- `eval.jsonl`은 **재기만** 한다. 학습 중 epoch마다 찍히는 eval 점수(원문 코드)는 지켜보기만 하고, 그걸 보고 epoch·lr을 고르거나 "가장 좋은 epoch"를 고르지 않는다. **마지막 epoch 모델**을 쓴다.
- 원문 확인 포인트의 "점수가 떨어지면 epoch를 줄이거나 lr을 낮춘다"는 `eval.jsonl`로 설정을 고르는 일이 되므로 이번에는 하지 않는다. 떨어지면 미통과로 적고, 고칠 방법은 "다음에 할 일"에만 쓴다.

## 5. 데이터 (직접 만듦)

원문은 "제공되는 `eval.jsonl` 60쌍, `train.jsonl` 282쌍"이라고 하지만 파일 자체나 받는 곳은 적혀 있지 않다(형식 예시 2줄뿐). 맥·프로젝트 파일·두 저장소의 모든 브랜치를 찾아봤지만 없었다. 그래서 재웅 결정(2026-10-23)으로 **원문 '데이터 준비' 방법대로 Claude가 직접 썼다.** 강사 제공 파일이 나중에 오면 그걸로 다시 하고 두 결과를 같이 적는다.

| | eval.jsonl | train.jsonl |
| --- | --- | --- |
| 규모 (원문 설명과 같게) | 문서 20 × 질의 3 = 60쌍 | 문서 94 × 질의 3 = 282쌍 |

| 만든 순서 | **먼저** 만들고 해시를 이 보고서에 적어 잠금 | eval 다음에, eval과 같은 사실을 다루지 않게 |
| sha256 | `8649476ea4289a09c7f8c5f211a8eeae8fce54633a00a04892bf91356a48c1cb` | `da16d4487d1d3f5a` (앞 16자리) |

- 수치는 원문처럼 **실습용 가상 운영 기준**이다. 실제 교육장 규정이 아니다.
- 데이터 파일은 커밋하지 않는다(`data/`는 `.gitignore`). 대신 위 해시로 같은 파일인지 확인할 수 있다.
- `check_data.py`로 점검(기준 0.35는 데이터를 보기 전에 정함): train·eval 똑같은 문장 0개, 글자 3개 묶음 겹침 최대 train-eval 문서 0.08, 질의 0.30, 3단계 문장과 0.12 → **겹침 없음**.

| 미세조정 (eg2-classroom) | **768** | **0.733** | 0.917 | 0.967 | **0.865** | 3.4분 (54스텝) |
| 기준 | 512 | 0.683 | 0.850 | 0.983 | 0.834 | |
| 미세조정 | 512 | 0.717 | 0.933 | 0.967 | 0.854 | |

- 학습 loss: 2.25(0.6 epoch) → 1.33 → 0.86 → 0.64 → 0.77(2.8 epoch), 평균 1.11. 줄어드는 방향이다.
- 학습 중 epoch마다 찍힌 768차원 eval: accuracy@1 0.717 → 0.733 → 0.733, ndcg@10 0.858 → 0.864 → 0.865. 지켜보기만 했고 마지막 epoch 모델을 그대로 썼다.
- 저장된 모델: `models/eg2-classroom`, `model.safetensors` 542MB (텍스트 부분만, bf16).

### 3단계 재확인 (미세조정 모델, `EG2_MODEL=models/eg2-classroom python test_text.py`)

| 질의 | 768 | 256 | 128 |
| --- | --- | --- | --- |

### 성공 기준 판정

| # | 기준 | 결과 | |
| --- | --- | --- | --- |
| 1 | 768차원 accuracy@1, ndcg@10 둘 다 상승 | 0.700 → 0.733 (+2문제), 0.847 → 0.865 | 충족 |
| 2 | 3단계 6칸 PASS | **4/6** (질의 1이 768·128에서 조도 문장을 1위로) | **미충족** |
| 3 | 저장·다시 불러 평가 | 됨 | 충족 |
| | **판정** | | **미통과** |

**왜 이렇게 나왔는지:**

- **도메인 점수는 조금 올랐다.** 60문제 중 1위로 맞힌 게 42개 → 44개. accuracy@3은 0.867 → 0.917로 더 크게 올랐다. 학습 데이터에 강의실 운영 문장 94개를 보여 준 만큼, "이 분야에서 질문과 답이 어떻게 이어지는지"를 조금 배운 것이다. 다만 60문제라 1문제가 0.017이어서, +2문제는 큰 차이라고 말하기 어렵다.
- **3단계 질의 1은 원래부터 아슬아슬했다.** 기준 모델도 1위(CO2)와 2위(조도)의 차이가 0.003~0.006뿐이었다. "졸리고 머리가 맑지 않아요"는 CO2(집중력)와 조도(눈 피로) 둘 다 그럴듯한 답이다. 미세조정이 벡터 공간을 조금만 움직여도 순서가 뒤집힐 수 있는 상태였고, 실제로 0.001~0.008 차이로 뒤집혔다.
- **학습 데이터가 그쪽을 일부러 안 다뤘다.** 3단계 재확인을 공정하게 하려고 학습 데이터에 3단계 문장(CO2 1000ppm·집중력, 조도 300lux)을 넣지 않았다. 그래서 "졸림 → CO2"를 가르친 적이 없고, 학습 데이터의 CO2 문장은 숫자 기준(800·1500ppm)·환기 방법 위주였다. 그 결과 모델이 CO2를 "졸림"보다 "환기·수치" 쪽에 더 가깝게 놓게 된 것으로 보인다(추정).
- **점수 전체 크기가 내려갔다.** 질의 1의 1위 점수가 0.718 → 0.502로 줄었다. MultipleNegativesRankingLoss는 오답과 멀어지게 학습하므로 비슷도 숫자 자체가 작아지는 게 흔하다. 순서만 보면 되니 이것 자체는 문제가 아니다.
- **데이터를 같은 사람이 썼다는 한계.** 학습·평가 데이터를 둘 다 Claude가 썼다(5번). 그런데도 상승 폭이 작았던 건, 기준 모델이 이미 0.700으로 이 정도 문장은 잘 찾고 있었기 때문으로 보인다.

- **보드 A에서 같은 평가**: 모델(542MB)과 데이터를 보드로 옮기고 `eval_ir.py`(기준·미세조정)와 3단계 재확인을 `~/practice.sh`로 돌린다. 맥과 같은 숫자가 나오는지 본다(bf16이라 소수점 셋째 자리는 조금 다를 수 있다). 결과는 7번에 적는다.
- 판정은 이번 결과(미통과)를 그대로 둔다. 원문 확인 포인트의 "epoch·lr 줄이기"는 `eval.jsonl`이나 3단계 결과를 보고 설정을 고르는 일이 되므로 하지 않았다. 다시 한다면 **eval과 별도인 검증용 데이터**(train에서 문서 단위로 일부 떼어 냄)를 먼저 만들고, 그걸로만 설정을 고른다.
- 강사 제공 `train.jsonl`·`eval.jsonl`을 받으면 같은 순서로 다시 하고 두 결과를 나란히 적는다.
- 8단계부터는 원문대로 원본 모델을 쓴다(미세조정 모델은 텍스트 전용이라 이미지 검색에 못 쓴다).

## 8. 2차 (맥, 2026-10-23) — 미리 정한 방법

재웅 방침: 통과할 때까지 다시 한다. 1차 결과(미통과)는 6번에 그대로 둔다. **eval.jsonl, 통과 기준(1번), 3단계 질문은 바꾸지 않는다.** 설정은 아래 연습 시험으로만 고르고, 진짜 시험(eval.jsonl, 3단계)은 고른 모델 하나로 **한 번만** 본다. 모든 시도를 여기에 적는다.

### 8-1. 1차 원인 분석과 바꿀 것

- 1차 미통과는 3단계 질의 1이 0.001~0.008 차이로 뒤집힌 것이다. 학습이 벡터 공간을 너무 많이 움직였을 수 있다(원문 확인 포인트: "점수가 떨어지면 epoch를 1~2로 줄이거나 lr을 1e-5로 낮춘다").
- 그래서 **학습 세기만** 바꿔 본다. 학습 데이터 내용은 바꾸지 않는다. 3단계 문장을 학습 데이터에 넣는 것은 시험 문제를 보고 답을 넣는 일이라 하지 않는다.

### 8-2. 연습 시험 (설정 고르기용, 이 순서로 먼저 만듦)

| 이름 | 만든 법 | 무엇을 보나 |
| --- | --- | --- |
| `dev.jsonl` | `split_dev.py`: train.jsonl 94문서 중 20문서(씨앗 0)를 떼어 냄 → 60쌍. 나머지 74문서 222쌍은 `train2.jsonl` | 강의실 분야 검색 |
| `general_dev.jsonl` | 강의실과 무관한 일상 주제(건강·요리·여행·IT·돈·공부 등) 20문서 × 질의 2 = 40쌍을 새로 씀. `check_data.py`로 eval·3단계와 안 겹침 확인 | 일반 검색이 망가졌는지 |

### 8-3. 후보와 고르는 규칙 (돌리기 전에 정함)

후보 4개, 나머지 설정은 원문 그대로. 모두 `train2.jsonl`로 학습하고 eval.jsonl은 보지 않는다(`--eval ''`).

| 후보 | lr | epoch |
| --- | --- | --- |
| A (1차와 같음) | 2e-5 | 3 |
| B | 1e-5 | 3 |
| C | 2e-5 | 1 |
| D | 1e-5 | 1 |

1. 768차원 `general_dev` ndcg@10이 기준 모델보다 0.01 넘게 떨어진 후보는 뺀다.
2. 남은 후보 중 768차원 `dev` ndcg@10이 가장 높은 것을 고른다. 차이가 0.005 이하면 학습을 덜 한 쪽(D → C → B → A 순)을 고른다.
3. 남은 후보가 없으면 `general_dev` ndcg@10이 가장 높은 것을 고른다.
4. 고른 설정으로 **전체 `train.jsonl`(282쌍)** 로 다시 학습해 `models/eg2-classroom-r2`에 저장하고, 1번 기준으로 한 번 판정한다.

### 8-4. 결과

연습 시험 (768차원, train2로 학습한 후보)

| | dev ndcg@10 | dev accuracy@1 | general_dev ndcg@10 | 학습 시간 |
| --- | --- | --- | --- | --- |
| 기준 모델 | 0.954 | 0.900 | 0.982 | - |
| A (2e-5, 3) | **0.956** | 0.900 | 0.978 | 2.7분 |
| B (1e-5, 3) | 0.955 | 0.900 | 0.982 | 3.2분 |

| D (1e-5, 1) | 0.954 | 0.900 | 0.982 | 1.3분 |

**판정: 미통과** — 기준 2·3은 충족, 기준 1(둘 다 **상승**) 미충족. 점수가 기준 모델과 똑같다.

**왜:** 연습 시험이 **너무 쉬웠다.** 기준 모델이 이미 dev 0.954, general_dev 0.982라 후보끼리 차이가 0.006 안이었다. 그래서 고르는 규칙이 사실상 "학습을 가장 덜 한 것"을 골랐고, lr 1e-5로 18스텝(그중 10%는 워밍업)만 학습한 모델은 거의 움직이지 않았다. 1차(많이 학습)는 도메인 점수가 오르는 대신 3단계 질의 1이 뒤집혔고, 2차(조금 학습)는 3단계를 지키는 대신 도메인 점수가 안 올랐다.

**주의(정직하게):** 이제 진짜 시험을 두 번 봤다. 3차의 후보 범위(A와 D 사이)를 정할 때 1·2차 결과를 알고 있다는 사실을 적어 둔다.

### 8-5. 3차 계획 (돌리기 전에 정함)

바꾸는 것은 **연습 시험을 어렵게** 하는 것뿐이다. 후보는 2차에서 train2로 이미 학습한 A·B·C·D 그대로.

| 이름 | 만든 법 |
| --- | --- |
| `dev` (어렵게) | dev 60질의를 dev 20문서 + train2 74문서 = **94문서** 중에서 찾게 한다(오답 후보를 4배 넘게 늘림) |
| `general_hard.jsonl` | 강의실과 무관한 일상 주제에서 **그럴듯한 오답이 짝으로 있는** 문서 16개(8쌍) × 질의 2 = 32쌍을 새로 씀. 같은 증상에 원인 두 개처럼, 한쪽만 정답. 3단계 문장·주제(CO2·냉방·조도)는 쓰지 않음 |

고르는 규칙:
1. 768차원 `general_dev` 또는 `general_hard`의 ndcg@10이 기준 모델보다 0.01 넘게 떨어진 후보는 뺀다.
2. 남은 후보 중 768차원 어려운 `dev` ndcg@10이 가장 높은 것을 고른다. 0.005 이하 차이면 학습을 덜 한 쪽(D → C → B → A).
3. 남은 후보가 없으면 `general_hard` ndcg@10이 가장 높은 것.
4. 고른 설정이 D면 2차와 같은 모델이므로 3차는 하지 않고 미통과로 끝낸다. 아니면 전체 train.jsonl로 다시 학습해 `models/eg2-classroom-r3`로 한 번 판정한다.
