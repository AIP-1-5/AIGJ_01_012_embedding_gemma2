# 4단계 영상 테스트 (텍스트로 사진·동영상 찾기)

> 상태: **보드 A 미통과 (2026-10-23)** — 768차원 질의 2가 1위를 놓침. 512차원은 3개 모두 정답. 동영상 통째 임베딩은 `torchcodec`이 없어 실패, 프레임 검색으로 대체
> 원문: 실습 README의 "4단계 영상 테스트"
> 앞 단계: [03-text-search.md](03-text-search.md) — 보드 A 통과 (텍스트 전용 GPU 최대 540 MB, 질의 2개 약 154 ms)
> 우리 보드: 보드 A, USB 웹캠 1대(이미 꽂혀 있음), 모니터 없음 → 사진·결과는 **노트북 브라우저**로 본다.

## 0. 이 단계에서 무엇을 하나

3단계까지는 글과 글을 비교했다. 4단계는 **비전 인코더**(사진을 숫자로 바꾸는 부분, 약 440M)를 같이 올려서 **글로 사진을 찾는다.**

1. 웹캠으로 강의실 사진 3~5장(빈 자리, 수업 중, 화이트보드 …)과 10초 동영상 1개를 찍는다.
2. 사진과 동영상을 각각 숫자 768개(벡터)로 바꾼다.
3. "사람이 없는 빈 강의실" 같은 **글** 질문도 벡터로 바꿔, 어느 사진과 가장 가까운지 본다.

글 벡터와 사진 벡터를 바로 비교할 수 있다는 것은 **글과 사진이 같은 벡터 공간에 있다**는 뜻이다. 8단계(웹캠에서 잘라 낸 물체를 글로 검색하고 이름을 다시 붙이기)가 바로 이 능력을 쓴다.

- 사진 한 장은 기본 280개 조각(토큰)으로, 동영상은 1초에 1장씩 뽑아 처리한다. 그래서 동영상은 사진보다 오래 걸린다.
- 비전 인코더를 같이 올리므로 3단계보다 메모리를 더 쓴다. 시작 전에 꼭 `free -h`를 본다.

## 1. 성공 기준 (먼저 적어 둔다)

원문 "확인 포인트"의 "각 질의의 1위 이미지가 사람 눈으로 봐도 맞는지"를, 사진 이름으로 자동 확인할 수 있게 정한다. **사진을 찍을 때 이름을 아래처럼 붙인다.**

| 질의 | 1위여야 하는 사진 | 그 사진에 찍을 것 |
| --- | --- | --- |
| 사람이 없는 빈 강의실 | `empty.jpg` | 사람 없이 책상·의자만 보이는 곳 |
| 학생들이 앉아 수업을 듣는 모습 | `class.jpg` | 사람이 앉아 있는 모습 (찍히는 사람에게 먼저 말한다) |
| 화이트보드에 쓴 글씨 | `board.jpg` | 글씨가 쓰인 화이트보드 |

- 나머지 1~2장(`monitor.jpg`, `door.jpg` 등)은 헷갈리게 하는 "다른 장면"이다. 이름은 자유.
- **통과**: 768차원과 512차원(원문: "멀티모달 검색은 768 또는 512차원")에서 질의 3개 모두 1위가 정답, 즉 6칸 PASS. 결과를 보고 사진 이름을 바꾸거나 다시 찍어 맞추지 않는다. 다시 찍었다면 그 사실과 이유를 결과에 적는다.
- 128차원은 참고로만 본다(원문: 영상·음성 품질이 약 75%로 떨어짐).
- **동영상**: 통째로 임베딩(`{"video": ...}`)이 되면 질의-동영상 유사도를 적는다. 디코딩이 실패하면 원문대로 프레임 사진 검색으로 대체하고, "동영상 통째로는 실패"라고 그대로 적는다. 동영상은 통과 조건이 아니다.
- 지연(ms)·메모리는 기록만 하고 6단계 표의 "+비전" 두 행에 쓴다.

## 2. 우리 보드에서는 원문과 이렇게 다르게 한다

| 원문 | 우리 보드에서 | 이유 |
| --- | --- | --- |
| RTSP IP 카메라에서 `ffmpeg`로 녹화 | **USB 웹캠**(`/dev/video0`)에서 `cam.py`(OpenCV)로 찍는다 | 우리 보드에는 USB 웹캠이 꽂혀 있다. 보드의 ffmpeg(NVIDIA Jetson 판 `n8.0.1`)는 웹캠(v4l2) 입력이 빠져 있어서 `-f v4l2`가 `Unknown input format`으로 실패했다(2026-10-23 확인) |
| (설치 없음) | `~/eg2`에 `opencv-python-headless==4.11.0.86` 설치 | 웹캠을 sudo 없이 읽으려고. 8단계에서도 쓴다. 4.12부터는 numpy 2를 요구해서 numpy 1.26.4와 맞는 4.11로 고정, 화면이 없어 headless 판 |
| 영상에서 뽑은 `frame_*.jpg`를 사진으로 검색 | 장면이 다른 사진을 **따로** 찍고 이름을 붙인다. 프레임은 `media/frames/`에 두고 동영상 실패 때만 쓴다 | 10초 영상의 프레임은 장면이 거의 같아서 "서로 다른 장면" 검색이 안 된다. 이름이 있어야 1위를 자동 판정한다 |
| 사진을 열어 보기 | 보드에서 `python3 -m http.server 8001`을 잠깐 켜고 **노트북 브라우저**로 본다 | 보드 모니터가 안 나온다. 8001은 우리 실습 앱 포트 |
| `~/eg2-lab`에서 `nano test_vision.py` | 저장소의 `test_vision.py`를 `git pull`로 받는다. `media/`는 `~/eg2-재웅/media` | 팀 규칙 6번. `media/`, `*.jpg`, `*.mp4`는 `.gitignore`에 있어 커밋되지 않는다 |
| `python test_vision.py` | `~/practice.sh 재웅 python test_vision.py`. 카메라로 찍는 `ffmpeg`도 `~/practice.sh`로 | 자물쇠: 카메라는 한 번에 한 프로그램만 열 수 있다 |
| 1위 3개만 출력 | PASS/FAIL, 2위와 점수 차이, 768/512/128차원 비교, GPU 메모리 최대 | 기준 확인을 눈으로 세지 않게 |
| 동영상 오류 시 줄을 주석 처리 | 코드가 실패를 잡아 이유를 출력하고 **프레임 검색으로 자동 대체** | 보드에서 코드를 고치지 않으려고 |
| 확장 과제(텍스트+이미지 혼합)는 따로 | 같은 실행에서 `board.jpg`로 한 번 해 본다(참고) | 모델을 두 번 올리지 않으려고 |
| (메모리 설정 없음) | 오디오 인코더 안 올림, GPU 몫 `0.3`, `batch_size=2`, `inference_mode`, 끝나면 해제 | 팀 문서 11번, 메모리 아끼기 원칙 |

pip 설치는 OpenCV 하나다(3-2). 동영상 디코딩용 `av`는 2단계에서 이미 깔았다.

## 3. 순서 (보드 A, 자기 계정으로 SSH)

SSH는 노트북에서 Tailscale 주소로 `ssh jaeung@100.113.228.46` (기본). 같은 교육장 망이면 와이파이 `172.27.108.43`도 된다.

### 3-1. 시작 전 확인 (읽기만)

**무엇을, 왜:** 누가 보드·카메라를 쓰는 중인지, 메모리가 넉넉한지, torch가 그대로인지, 센서 서비스가 살아 있는지, 웹캠이 보이는지 본다.

```bash
echo "== 누가 쓰는 중?"; cat /tmp/practice.who.* 2>/dev/null || echo "아무도 안 씀"
echo "== 메모리"; free -h                   # available 3GB 이상
echo "== 디스크"; df -h / | tail -1          # 사진·영상은 몇 MB뿐이지만 확인
source ~/eg2/bin/activate
echo "== torch"; pip freeze | grep -E '^(torch|torchvision|torchaudio|av)=='   # torch·torchvision cu132, av 있음, torchaudio 없음
echo "== 센서 서비스"; curl -s -m 3 localhost:8080/health || echo "응답 없음"
echo "== 웹캠"; ls /dev/video*; groups | grep -qw video && echo "video 그룹 OK" || echo "video 그룹 아님"
```

- 웹캠은 보통 `/dev/video0`(영상)과 `/dev/video1`(정보용) 두 개가 보인다. `/dev/video0`이 없으면 화면을 보낸다.
- `video 그룹 아님`이면 카메라를 못 연다. 화면을 보낸다(관리 계정으로 한 번 설정해야 한다).
- 센서 서비스 "응답 없음"이면 여기서 멈춘다.

### 3-2. 코드 받기

```bash
cd ~/eg2-재웅 && git pull && git log -1 --oneline   # 보고서에 적을 커밋
ls test_vision.py cam.py && mkdir -p media/frames
```

OpenCV 설치 (한 번만). torch 고정과 numpy 고정을 같이 걸어서 다른 것이 바뀌지 않게 한다.

```bash
source ~/eg2/bin/activate
pip install -c ~/eg2/torch-pin.txt "numpy==1.26.4" "opencv-python-headless==4.11.0.86"
pip freeze | grep -E '^(torch|torchvision|torchaudio|numpy|opencv-python-headless)=='   # torch·torchvision cu132, numpy 1.26.4, opencv 4.11.0.86, torchaudio 없음
python -c "import cv2; print(cv2.__version__)"
```

- torchaudio 줄이 보이면 `pip uninstall -y torchaudio`.

### 3-3. 사진 찍기 (웹캠, 장면마다 한 장)

**무엇을, 왜:** 검색할 사진을 만든다. 웹캠을 손으로 들고 장면을 향하게 한 뒤 한 줄씩 실행한다. `cam.py`는 켜자마자 나오는 어두운 장면 15장을 버리고 다음 장면을 저장한다. 카메라를 잡는 일이라 `~/practice.sh`를 거친다.

```bash
cd ~/eg2-재웅 && source ~/eg2/bin/activate
~/practice.sh 재웅 python cam.py snap empty     # 사람 없는 책상·의자 쪽
~/practice.sh 재웅 python cam.py snap class     # 사람이 앉아 있는 쪽 (찍히는 사람에게 먼저 말하기)
~/practice.sh 재웅 python cam.py snap board     # 글씨가 쓰인 화이트보드
~/practice.sh 재웅 python cam.py snap monitor   # (다른 장면) 모니터나 창문, 문 등
```

- `/dev/video0을 열 수 없다` → 다른 프로그램이 카메라를 쓰는 중인지 `cat /tmp/practice.who.*`. 그래도 안 되면 `CAM=1 python cam.py ...`
- 노트북·휴대폰 사진을 써도 된다. 그때는 노트북에서 `scp empty.jpg class.jpg board.jpg jaeung@100.113.228.46:~/eg2-재웅/media/` (이름 약속은 같다)

### 3-4. 동영상 10초 찍기 (프레임도 같이)

**무엇을, 왜:** 동영상 검색용 10초 영상을 만든다. 수업 중인 쪽(사람이 앉아 있는 곳)을 10초 동안 비춘다. 찍는 동안 2초마다 한 장씩 `media/frames/`에도 저장하는데, 동영상 디코딩이 안 될 때 대신 쓴다.

```bash
cd ~/eg2-재웅 && source ~/eg2/bin/activate
~/practice.sh 재웅 python cam.py clip 10
ls -lh media/*.jpg media/*.mp4 media/frames/
```

영상에 무엇을 찍었는지(예: "앉아 있는 팀원 2명") 한 줄 적어 둔다. 질의-동영상 유사도를 해석할 때 쓴다.

### 3-5. 노트북 브라우저로 사진 확인

**무엇을, 왜:** 사진이 이름대로 찍혔는지 사람 눈으로 먼저 본다(검색을 돌리기 **전에**). 보드에 작은 파일 서버를 잠깐 켠다.

```bash
cd ~/eg2-재웅
~/practice.sh 재웅 python3 -m http.server 8001 -d media
```

노트북 브라우저에서 `http://100.113.228.46:8001` (Tailscale). 사진을 다 봤으면 **Ctrl+C로 끈다.** 켜 둔 동안은 자물쇠가 잠겨 있어서 다른 `~/practice.sh` 명령이 막힌다.

이름과 내용이 안 맞으면(예: `empty.jpg`에 사람이 찍힘) 3-3으로 돌아가 다시 찍는다. 이것은 검색 결과를 보기 전이라 괜찮다.

### 3-6. 영상 검색 실행 (성공 기준)

**무엇을, 왜:** 사진 → 동영상 → 혼합 입력 순으로 벡터로 바꾸고, 질의 3개마다 1위 사진을 찾는다. `PASS`가 768·512에서 6번 나오면 통과다.

```bash
cd ~/eg2-재웅 && source ~/eg2/bin/activate
free -h | head -2                           # available 3GB 미만이면 실행하지 않고 화면을 보낸다
~/practice.sh 재웅 python test_vision.py 2>&1 | tee /tmp/eg2-04-vision.txt
```

도는 동안 다른 SSH 창에서 `free -h`를 한 번 보면 메모리 기록에 쓴다(선택).

출력 모양 (숫자는 자리만 표시):

```text

모델 로드 x.x s
이미지 4장: xxx ms

[dim=768]
  사람이 없는 빈 강의실 -> [('empty', 0.xxx), ...]  2위와 차이 0.xxx  PASS
  ...
[dim=512]
  ...
[dim=128]  (참고, 통과 조건 아님)
  ...

[동영상]
동영상 1개: xxxx ms
질의-동영상 유사도: [0.xxx 0.xxx 0.xxx]  (순서: ...)

[확장 과제] 텍스트+이미지 혼합 입력 (참고)
  ...

GPU 메모리 최대 xxxx MB
동영상: 통째로 임베딩 성공
결과: 768·512차원에서 질의 3개 모두 1위 정답 (통과)
```

`/tmp/eg2-04-vision.txt` 내용, 3-4에 적은 영상 내용 한 줄, 실행 중·후 `free -h`를 보내 주면 아래 결과 표를 채운다.

## 4. 자주 나는 오류

| 화면에 나온 것 | 원인 | 할 일 |
| --- | --- | --- |
| `동영상 디코딩 실패: ...` | aarch64용 동영상 읽기 도구 문제 | 코드가 프레임 검색으로 자동 대체한다. 실패 메시지를 그대로 보낸다 (원문 6단계 표: `pip install av` 확인) |
| `CUDA out of memory`, `Killed` | 메모리 부족 (비전 인코더 + 동영상) | `free -h`, `cat /tmp/practice.who.*`를 보낸다. 센서 서비스는 끄지 않는다 |
| `media/*.jpg 사진이 없다` | 3-3을 안 했거나 다른 폴더에서 실행 | `cd ~/eg2-재웅` 후 `ls media` |
| `판정 못 함 (empty.jpg 없음)` | 이름 약속과 다른 이름 | 사진 이름을 확인한다 (`empty`, `class`, `board`) |
| `OfflineModeIsEnabled` / `does not appear to have a file` | 비전 인코더 파일이 캐시에 없음 | `HF_HUB_OFFLINE=0 hf download google/embeddinggemma-2`로 받고 재실행 |
| 점수가 `nan` | float16 사용 | `eg2.py`는 bfloat16이다. 코드를 고치지 않았는지 본다 |
| 브라우저에서 8001이 안 열림 | 서버가 꺼졌거나 다른 망 | 3-5 창이 켜져 있는지, 노트북이 같은 망·Tailscale인지 본다 |

| 다시 찍음 | 처음 4장을 연달아 찍어 이름과 장면이 안 맞아서, **검색을 돌리기 전에** 한 장씩 5초 여유를 두고 다시 찍었다(브라우저로 확인). 검색 결과를 본 뒤에는 다시 찍지 않았다 |
| 모델 로드 | 5.1 s (텍스트 + 비전, 오디오 안 올림) |
| 이미지 4장 지연 | 1941 ms (예열 1회 뒤, batch 2) |
| 768차원 | 질의1 `empty` **PASS** (차이 0.070) / 질의2 `empty`가 1위, `class` 2위 **FAIL** (차이 0.009) / 질의3 `board` **PASS** (`class`와 0.584 동점, 차이 0.000) |

**왜 이렇게 나왔는지:**

- **빈 강의실은 확실히 맞혔다.** 세 차원 모두 1위이고 2위와 차이도 0.065~0.076으로 가장 컸다. "사람이 없다"는 특징이 사진에 분명히 드러났다는 뜻이다.
- **"수업 듣는 모습"은 `empty`와 `class`를 거의 구별 못 했다.** 768에서 0.634 대 0.625로 0.009 차이로 놓쳤고, 512에서는 0.001 차이로 겨우 맞혔다. 두 사진이 같은 강의실의 책상·의자를 640x480으로 찍은 것이라 화면 대부분이 비슷하다. 사람이 작게 찍히면 "사람이 앉아 있다"는 차이가 사진 전체 벡터에 조금밖에 안 담긴다. 3단계 질의1(차이 0.003~0.007)처럼 "겨우 맞히거나 겨우 틀리는" 경우다.
- **화이트보드 질의는 동점으로 맞혔다(768).** 사진이 화이트보드가 아니라 컴퓨터 화면 글자라서 질의("화이트보드에 쓴 글씨")와 뜻이 완전히 같지 않다. 그래도 512·768 모두 `board`가 1위인 것은 "글씨"를 알아봤다는 뜻으로 볼 수 있다. 동점이라 운이 섞였다.
- **점수 폭이 좁다.** 모든 점수가 0.57~0.67 사이다. 3단계 텍스트 검색(0.59~0.73)보다 좁다. 같은 방에서 같은 웹캠으로 찍은 사진이라 서로 닮았고, 질의 세 개도 모두 "강의실" 이야기라 사진 하나하나와의 차이가 작다.
- **128차원은 2개 틀렸다.** 원문 확인 포인트("128차원에서는 영상 품질이 약 75%로 떨어진다")와 맞는다. 사진 검색은 768이나 512를 쓴다.
- **동영상 통째 임베딩은 이 보드에서 아직 안 된다.** transformers가 동영상을 읽을 때 `torchcodec`을 찾는데 설치돼 있지 않고, 옛 방식(`torchvision.io.read_video`)은 지금 torchvision에서 없어졌다. 원문 6단계 표의 `pip install av`로는 해결되지 않는다(이미 있음). 대체한 프레임 검색에서는 "수업 듣는 모습"의 프레임 평균(0.609)이 가장 높아, 사람이 앉아 있는 쪽을 찍은 영상 내용과 맞는 방향이다.
- **혼합 입력**은 모든 질의 점수를 0.69~0.73으로 끌어올렸지만, 1위가 "화이트보드"에서 "빈 강의실"로 바뀌었다. 같이 넣은 글자 "강의실"이 사진보다 강하게 작용해서, 질의 세 개 모두에 공통인 "강의실" 쪽으로 쏠린 것으로 보인다.
- 메모리는 GPU 최대 1022 MB로, 비전 인코더 때문에 텍스트 전용의 약 2배였다. 끝난 뒤 available이 거의 그대로(3.6 → 3.5Gi)였고 센서 서비스도 영향이 없었다. 스왑이 늘어난 것은 모델을 올릴 때 다른 메모리가 잠깐 밀려난 것이다.

**다음에 할 일:**

- 6단계 표 "+비전" 행: 이미지 4장 1941 ms, 동영상은 통째로 못 재서 "프레임 5장 2317 ms(대체)"로 적고, GPU 최대 1022 MB.
- 동영상 통째 임베딩을 하려면 `torchcodec`이 필요하다. Jetson(aarch64) + torch 2.14.1 cu132에 맞는 판이 있는지 먼저 확인하고, `-c ~/eg2/torch-pin.txt`로만 설치를 시도한다(torch를 바꾸려 하면 멈춘다). 성공 기준에는 들어가지 않으니 선택이다.
