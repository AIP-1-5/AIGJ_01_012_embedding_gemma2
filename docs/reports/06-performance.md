## 0. 이 단계에서 무엇을 하나

3~5단계에서는 "검색이 맞는가"를 봤다. 6단계는 **"보드에 얼마나 부담이 되는가"**를 잰다.
EmbeddingGemma 2는 필요한 인코더만 골라 올릴 수 있다. 원문 표의 4가지 모양을 차례로 올려 보면서 각각 세 가지를 잰다.

| 모양 | 올리는 것 | 원문 로드 크기 |
| --- | --- | --- |
| 텍스트 전용 | 글 인코더 | 270M |
| +비전 | 글 + 사진 인코더 | 440M |
| +오디오 | 글 + 소리 인코더 | 570M |
| 전체 | 글 + 사진 + 소리 | 740M |

- **로드 후 RAM**: 모델을 올린 뒤 보드 전체 메모리 사용량. Jetson은 CPU와 GPU가 8GB를 같이 쓰므로 GPU에 올린 모델도 여기에 잡힌다.
- **지연**: 입력을 넣고 벡터가 나올 때까지 걸린 시간. 첫 번째는 준비(예열) 시간이 섞이니 **두 번째 값**을 적는다(원문).
- **GPU 사용률**: 그동안 GPU가 얼마나 바빴는지(`tegrastats`의 `GR3D_FREQ`).

이 숫자가 있으면 8~10단계(웹캠 + YOLO + 임베딩을 같이 올림)에서 "보드에 무엇을 같이 올릴 수 있나"를 미리 가늠할 수 있다. 센서 서비스(약 1.5GB)와 다른 계정이 이미 쓰는 메모리를 빼고 남는 자리가 얼마인지가 핵심이다.

"문제 해결"은 원문의 자주 겪는 문제 표를 우리가 1~5단계에서 실제로 겪은 것과 맞춰 보는 부분이다(4절).

## 1. 성공 기준 (먼저 적어 둔다)

원문에는 합격선 숫자가 없고 "표를 직접 채운다"만 있다. 그래서 아래처럼 정한다. 결과를 본 뒤 기준을 바꾸지 않는다.

1. **표 5줄을 모두 실측으로 채운다**: 텍스트 전용(질의 2개), +비전(이미지 5장), +비전(동영상 10초), +오디오(WAV 3개), 전체(혼합).
   - 동영상 줄은 4단계처럼 통째 임베딩이 안 되면 **원문 6단계 표의 해결 방법**(추출한 프레임을 이미지로 입력)으로 잰 값을 허용한다. 대신 표에 "대체"라고 적는다.
2. **각 줄의 세 칸**(로드 후 RAM, 지연 = 두 번째 실행 값, GPU 사용률)이 모두 숫자다.
3. **안전**: 메모리 감시 때문에 멈춘 줄이 없고, 줄마다 끝난 뒤 센서 서비스 `/health`가 `ok`다.

세 가지를 다 만족하면 **통과**. 메모리가 모자라 건너뛴 줄이 있으면 그 줄은 "측정 안 함(메모리)"로 적고 **미통과**로 둔다. 다른 날 다시 재는 것은 괜찮지만, 그 사실을 같이 적는다.

참고로만 볼 것(통과 조건 아님): 원문 로드 크기 순서대로 RAM이 텍스트 < +비전 < +오디오 < 전체로 늘어나는지, 3~5단계에서 잰 지연과 비슷한지.

## 2. 우리 보드에서는 원문과 이렇게 다르게 한다

| 원문 | 우리 보드에서 | 이유 |
| --- | --- | --- |
| 다른 터미널에서 `sudo tegrastats`를 켜 두고 눈으로 표를 채움 | `bench.py`가 `tegrastats`(sudo 없이)를 0.2초마다 읽어 자동으로 적는다. `tegrastats`가 안 되면 `/proc/meminfo`와 GPU `load` 파일로 대신 읽고 그렇게 적는다 | sudo는 사용자만 쓴다(팀 규칙). 0.15초짜리 텍스트 검색은 1초 간격 화면으로는 GPU 사용률이 안 잡힌다 |
| GPU 사용률은 테스트 도는 동안의 값 | 같은 입력을 **3초 이상 반복**하는 동안의 평균(최대도 같이) | 한 번 실행이 짧아(0.15~2초) 순간값으로는 0% 또는 우연한 값이 나온다 |
| 로드 후 RAM 한 숫자 | 로드 **전·후**를 다 적고, 늘어난 양도 적는다 | 보드 전체 RAM에는 센서 서비스와 다른 계정 프로그램도 들어 있다. 우리 모델 몫은 "늘어난 양"이다 |
| 이미지 5장 | 남아 있는 사진(사람이 안 찍힌 4단계 사진)을 돌려 써서 5장을 채운다 | 4단계 사람 사진은 약속대로 지웠다. 사진 내용은 계산량에 영향이 없다(사진마다 같은 280조각) |
| 동영상 10초 | `media/clip.mp4`가 있고 통째 임베딩이 되면 그 값. 안 되면 프레임 사진 10장(원문: 1초에 1장 × 10초)으로 대체 | 4단계에서 `torchcodec`이 없어 통째 임베딩이 실패했다. 영상도 지웠을 수 있다 |
| 전체 모양에서 "혼합" | 질의 2개 + 이미지 5장 + WAV 3개를 차례로 넣은 합 | 한 번의 encode에 종류를 섞어 넣는 것은 확인되지 않아서, 3~5단계와 같은 방식으로 나눠 넣는다 |
| (메모리 설정 없음) | 모양마다 **따로 프로세스**로 실행(끝나면 완전히 해제), 시작 전 available 3GB 미만이면 그 모양은 건너뜀, 도는 중 1.2GB 미만이면 다음 측정 안 함, **1GB 미만이면 그 자리에서 바로 종료**, GPU 몫 `0.3`, `~/practice.sh`(2500MB 제한) | 5단계(텍스트+오디오)에서 실행 중 available이 1.8GB까지 내려갔다. 전체 모양은 더 무겁다 |

이번 단계는 **pip 설치가 없다.**

## 3. 순서 (보드 A, 자기 계정)

### 3-1. 시작 전 확인 (읽기만)

**무엇을, 왜:** 누가 보드를 쓰는지, 메모리, 다른 계정이 무엇을 돌리는지(5단계에서 메모리를 같이 먹었다), 센서 서비스, 측정에 쓸 사진·소리가 남아 있는지 본다.

```bash
echo "== 누가 쓰는 중?"; cat /tmp/practice.who.* 2>/dev/null || echo "아무도 안 씀"
echo "== 메모리"; free -h
echo "== 메모리 많이 쓰는 프로그램"; ps -eo user,rss,comm --sort=-rss | head -8
echo "== 센서 서비스"; curl -s -m 3 localhost:8080/health || echo "응답 없음"
echo "== tegrastats"; command -v tegrastats || echo "없음"
cd ~/eg2-재웅 && git pull && git log -1 --oneline
echo "== 자료"; ls media/*.jpg media/*.wav media/clip.mp4 media/frames 2>&1
```

- 멈출 조건: 누가 쓰는 중이거나, available이 3GB 미만이거나, 센서 "응답 없음"이면 여기서 멈추고 결과를 보낸다.
- `media/*.jpg`가 하나도 없으면 +비전·전체 줄을 못 잰다. 그때는 멈추고 알린다(사람이 안 찍힌 사진 몇 장만 다시 찍으면 된다).
- `class.jpg`(사람이 찍힌 사진)가 아직 남아 있으면 4단계 약속대로 지우지 않은 것이다. 측정에 쓰지 않도록 알려 준다.

### 3-2. 측정 (모양 4개를 차례로, tmux 안에서)

**무엇을, 왜:** 모양마다 따로 실행해서 매번 메모리가 비어 있는 상태에서 잰다. 한 모양이 끝날 때마다 센서 서비스를 확인하고, 응답이 없으면 바로 멈춘다. 전체 2~3분 걸린다.

```bash
cd ~/eg2-재웅 && source ~/eg2/bin/activate
rm -f media/bench.jsonl      # 이번 측정만 표에 남긴다
for c in text vision audio all; do
  echo "===== $c  $(date +%H:%M:%S)"; free -m | sed -n 2p
  ~/practice.sh 재웅 python bench.py $c; echo "종료 코드 $?"
  curl -s -m 3 localhost:8080/health || { echo "!! 센서 응답 없음 → 멈춤"; break; }
  echo; sleep 10              # 메모리가 다 풀릴 때까지 잠깐 쉰다
done
python bench.py table        # 모델을 안 올리고 기록만 표로 출력
free -h; curl -s -m 3 localhost:8080/health
```

- 종료 코드 `0`: 정상. `1`: 시작 전 available 3GB 미만(그 모양 건너뜀) 또는 다른 오류. `3`: 도는 중 1.2GB 아래로 내려가 일부만 잼. `4`: 1GB 아래로 내려가 바로 멈춤.
- 화면 전체(특히 각 모양의 "지연 3번", "GPU 사용률", "RAM", "대체 이유" 줄과 마지막 표)를 그대로 보낸다.

### 3-3. 끝난 뒤

- `media/bench.jsonl`은 측정 기록이라 남겨 둬도 된다(커밋은 안 함).
- 센서 서비스 `/health`가 `ok`인지 마지막으로 본다(3-2 마지막 줄).

## 4. 문제 해결: 원문 "자주 겪는 문제"와 우리가 실제로 겪은 것

| 원문 증상 | 우리 보드에서 | 어떻게 했나 |
| --- | --- | --- |
| `torch.cuda.is_available()`가 False (PyPI torch로 덮어씀) | 겪지 않음 | 2단계부터 모든 pip 설치에 `-c ~/eg2/torch-pin.txt`. 대신 **원문 표에 없는 문제**: `sentence-transformers[audio]`가 torchaudio 2.11.0을 딸려 깔았다(핀 파일로 못 막음) → 설치 직후 `pip uninstall -y torchaudio` |
| 임베딩 NaN (float16) | 겪지 않음 | `eg2.py`가 처음부터 `bfloat16`으로 올린다 |
| `CUDA out of memory` / 강제 종료 | 종료는 없었다. 다만 5단계 실행 중 available이 **1.8GB**까지 내려감(다른 계정 `yj` 프로그램이 같이 씀) | 안 쓰는 인코더 안 올림, batch 2, GPU 몫 0.3, `~/practice.sh` 2500MB 제한, 실행 전 `free -h`. 6단계는 여기에 실행 중 감시(1.2GB/1GB)를 더했다 |
| `{"video": ...}` 디코더 오류 | **겪음**(4단계): `ImportError: torchcodec is not installed` | 원문 해결책 `pip install av`는 소용없었다(av 19.0.2 이미 있음). transformers가 지금은 `torchcodec`을 찾는다. 원문의 두 번째 방법(프레임 사진으로 입력)으로 대체 |
| `prompt_name`을 찾을 수 없음 | 겪지 않음 | sentence-transformers 6.2.0 (6.1.0 이상) |
| 오디오 검색이 무작위에 가까움 (샘플레이트·채널) | 겪지 않음 | `make_audio.py`가 16 kHz 모노로 바꾸고, `test_audio.py`가 형식이 다르면 멈춘다. 5단계 미통과(4/6)는 형식 문제가 아니라 점수 차가 0.008로 작아서다 |
| 모델 다운로드 느림·실패 | **원인이 달랐다**: 학교 유선망이 보드를 미등록 기기로 막아(NAC) GitHub·Hugging Face 인증서 오류 | 네트워크 쪽에서 해결(고정 IP). 인증서 검사는 끄지 않았다. 모델은 다 받은 뒤 `HF_HUB_OFFLINE=1`로 캐시에서 로드 |
| (GPU 메모리 빠듯하면) GGUF Q8_0 310MB로 대체 | 안 해 봄 | 선택. 6단계 표에서 텍스트 전용 RAM이 넉넉하면 필요 없다 |
