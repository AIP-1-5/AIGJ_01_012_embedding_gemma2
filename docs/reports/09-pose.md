## 0. 이 단계에서 무엇을 하나

8단계는 "물체"를 찾았다. 9단계는 **사람의 몸짓**을 알아본다.

1. **YOLO11n-pose**가 웹캠 영상에서 사람마다 관절 17개(코, 눈, 귀, 어깨, 팔꿈치, 손목, 엉덩이 …)의 위치를 찾는다.
2. 관절 좌표끼리의 관계로 동작을 정한다. 예: 두 손목이 어깨보다 충분히 위에 있으면 "만세".
3. 결과를 브라우저에서 영상(뼈대 그림)과 "동작별 횟수", "동작 기록" 표로 본다.

거리가 달라도 같은 기준이 되도록 모든 거리를 **어깨 너비로 나눠** 비교한다(가까이 서면 어깨도 크게 보이니까). 이미지에서 y가 작을수록 위쪽이다.

| 동작 | 판정 규칙 (원문) | 종류 |
| --- | --- | --- |
| 만세 | 양쪽 손목이 어깨보다 어깨 너비의 0.3배 이상 위 | 정지 자세 |
| 한팔들기 | 한쪽 손목만 위 기준을 만족 | 정지 자세 |
| 손흔들기 | 한팔들기 상태에서 1.5초 동안 손목이 좌우로 2번 이상 방향 전환 | 시간 패턴 (9-2부터) |
| 악수 | 두 사람의 손목이 어깨 너비의 0.5배 이내, 높이는 가슴~허리 | 2인 자세 |

8단계와 같이 **문제 확인 → 개선 → 확장** 순서다.

| 순서 | 실행 | 무엇을 확인하나 |
| --- | --- | --- |
| 9-1 문제 확인 | `--raw` | 한 프레임만 보고 판정하면 라벨이 깜빡여 횟수가 부풀고, 손 흔들기를 "한팔들기"와 구분하지 못한다 |
| 9-2 개선 | (옵션 없음) | 최근 0.6초 중 60% 이상인 라벨만 확정(다수결) + 손목의 좌우 움직임 1.5초를 보고 손 흔들기를 따로 판정 |
| 9-3 데이터 모으기 | `--record` | 관절 좌표(사진 아님)를 CSV로 저장. **파일 이름이 정답 라벨**이다 |
| 9-4 비교 | | 9-1과 9-2의 횟수를 실제 횟수와 비교한 표 |
| 9-5 행동 패턴 | `--behavior` | 한 사람의 몇 초~수십 초 기록으로 "지나감 / 힐끗 봄 / 관심 있음 / 머무름"을 정한다(머리가 카메라를 향한 시간 + 움직이는 속도) |
| 9-6 학습 모델 | `--model` | 9-3 데이터로 작은 **GRU**(시간 순서를 읽는 신경망)를 맥에서 학습. 규칙으로 못 적는 박수·팔짱도 알아보게 한다 |

핵심 개념: **규칙은 사람이 정한 경계선, 학습은 데이터에서 찾은 경계선이다.** 9-1·9-2·9-5는 사람이 정한 숫자(0.3배, 0.6초, 3초 …)로 판정하고, 9-6은 녹화한 예시를 보고 경계를 스스로 찾는다.

### EmbeddingGemma 2와 7·8단계 결과가 필요한가? → 필요 없다

원문: "EmbeddingGemma는 쓰지 않아 메모리가 적게 든다." 9단계는 YOLO 포즈 모델만 쓴다. 그래서 7단계(미세조정)·8단계 결과와 상관없이 준비할 수 있다. 다만 **8단계에서 설치한 ultralytics·fastapi를 그대로 쓰고, 같은 웹캠·같은 포트(8001)를 쓰므로** 보드 실행은 8단계가 끝난 뒤에 한다.

## 1. 성공 기준 (실행 전에 적어 둔다)

원문 9단계에는 "성공 기준" 표가 따로 없고, 9-4·9-5·9-6의 빈 표와 "확인 포인트"만 있다. 그래서 표를 빈칸 없이 채우는 것을 기본 기준으로 하고, 원문에 숫자가 없는 곳은 **우리가 정한 기준**(표에 "우리 기준"이라고 적음)을 실행 전에 정해 둔다. 결과를 본 뒤 기준을 바꾸지 않는다.

| # | 기준 | 근거 |
| --- | --- | --- |
| 1 | 네 방식이 모두 켜지고 브라우저 제목 옆에 `[raw]`, `[smooth]`, `[smooth +behavior]`, `[smooth +behavior +model]`이 보인다 | 9-1 1번, 9-2, 9-5, 9-6 |
| 2 | 검출 fps **10 이상** (기본 해상도 또는 `SIZE=640x480`) | 확인 포인트 "손 흔들기 판정에는 최소 10 fps 이상" |
| 3 | 9-4 표(실제 3회씩 × 5줄)의 raw·smooth 칸을 빈칸 없이 채운다 | 9-1 4번, 9-2 3번 |
| 4 | smooth에서 만세·한팔들기 횟수가 raw보다 실제(3회)에 같거나 더 가깝다 | 9-2 "깜빡임을 없앤다" |
| 5 | 손 흔들기 3번 중 smooth에서 `WAVE`가 **2번 이상** 기록된다 (raw에는 손 흔들기 판정이 없어 0이 정상) | 9-2 2번 (우리 기준: 3번 중 2번) |
| 6 | 9-3 데이터: 동작 `idle`·`wave`·`clap`·`arms_crossed` 각 **30초 이상**, 행동 `passing`·`glance`·`interested` 각 **10회 이상**. 참여한 사람 수를 적는다 (원문 권장 3명 이상, 모자라면 모자란 대로 적는다) | 9-3, 9-6 표 "필요한 데이터" |
| 7 | 9-5 표를 채우고, 4가지 시나리오 × 3번 = 12번 중 **8번 이상** 기대 패턴이 나온다 | 9-5 3·4번 (우리 기준: 3번 중 2번 비율) |
| 8 | 9-6: 맥에서 동작·행동 모델을 학습해 **검증 정확도와 혼동 행렬**을 적고, 보드에서 `--model`로 실행해 비교표를 채운다. 박수·팔짱 중 **1개 이상**을 학습 모델이 알아본다(규칙으로는 "불가") | 9-6 실행 절차·비교표 |
| 9 | "처음 본 사람" 칸은 **학습 데이터에 참여하지 않은 사람**으로 채운다. 그런 사람이 없으면 "못 함"이라고 쓴다 | 9-6 "낯선 사람으로 평가한다" |
| 10 | 메모리로 멈추지 않고(종료 코드 4 없음), 끝난 뒤 센서 서비스 `/health` ok. 사진·영상은 저장하지 않고, `data/`·`models/`는 커밋하지 않는다 | 팀 규칙 |

- 미통과면 1차 기록은 그대로 두고, 원인과 바꿀 것을 먼저 적은 뒤 2차를 한다. 원문이 바꿔 보라고 한 손잡이는 이것뿐이다: fps가 낮으면 `SIZE=640x480`, 깜빡임 ↔ 반응 속도는 `SMOOTH_S`, 흔드는 폭은 `is_wave`의 0.15, 행동 패턴은 `FACE_TH`·`INTEREST_S`·`MOVE_TH`, 학습은 "헷갈리는 라벨만 더 녹화", 지나가는 데 4초가 안 걸리면 `--window`를 줄인다. 바꿨으면 값과 이유를 적는다.
- 9-6의 검증 정확도는 같은 녹화의 뒷부분이라 높게 나온다(원문). 그래서 이 숫자만으로 통과를 정하지 않고, 기준 8·9처럼 보드에서 실제로 해 본 결과를 같이 본다.

### 4-5. 9-3 학습 데이터 녹화 (`--record`)

**무엇을, 왜:** 9-6에서 GRU에게 보여 줄 "예시"를 모은다. 파일 이름이 정답이라, 녹화하는 동안 화면에는 **그 동작을 하는 사람 한 명만** 있어야 한다. 사진은 안 남고 관절 숫자만 남는다.

카메라 앞에 서 있으면 Ctrl+C를 못 누르므로 `timeout`으로 시간을 정한다. 앞 10초 정도는 모델을 불러오는 시간이라 **동작 하나에 50초**로 잡는다(실제 녹화 약 40초). 사람이 바뀌면 같은 명령을 다시 실행하면 같은 파일 뒤에 이어 붙는다.

```bash
cd ~/eg2-재웅 && source ~/eg2/bin/activate
mkdir -p data/action data/behavior
R() { timeout -s INT "$1" ~/practice.sh 재웅 python pose_app.py --record "$2"; }
# 동작: 라벨당 30초 이상, 사람마다 한 번씩. 각도·거리를 조금씩 바꿔 가며
R 50 data/action/idle.csv           # 아무 동작 안 함 (꼭 필요)
R 50 data/action/wave.csv           # 손 흔들기
R 50 data/action/clap.csv           # 박수 (규칙에 없는 새 동작)
R 50 data/action/arms_crossed.csv   # 팔짱
# 행동: 라벨당 10회 이상. 한 번 하고 화면 밖으로 3초 이상 나갔다가 다시
R 120 data/behavior/passing.csv     # 그냥 지나가기
R 120 data/behavior/glance.csv      # 걸으면서 2초쯤 카메라 쪽 보기
R 180 data/behavior/interested.csv  # 멈춰 서서 5초 이상 카메라 쪽 보기
wc -l data/action/*.csv data/behavior/*.csv
```

- 매번 끝날 때 `data/.../xxx.csv에 이번에 N줄 기록`이 찍힌다. 30초 × fps(예: 15) ≈ 450줄이면 정상. 0줄이면 사람이 안 잡힌 것이다.
- `wc -l` 결과와 **누가 몇 번 녹화했는지**(이름 말고 "사람 A/B/C")를 적어 둔다(기준 6).
- 9-6 "처음 본 사람" 평가용 한 명은 여기서 **녹화하지 않는다**.

9-1에서 본 것 (2026-10-23):

- 원문이 말한 "문제"가 그대로 나왔다. 만세는 실제 6회인데 16, 한팔들기는 실제 3회인데 37이다. 팔을 올리는 중간에 한쪽 손목만 기준선을 먼저 넘는 프레임이 생겨 만세↔한팔들기가 0.1초 간격으로 바뀌었고, 바뀔 때마다 한 번씩 셌다.
- 악수 0회: 처음에는 옆모습에서 어깨 너비가 작아져(코드가 최소 20px로 막음) "손목 거리 < 어깨 너비 × 0.5"와 높이 범위가 아주 좁아지기 때문이라고 짐작했다. 그런데 같은 규칙인 9-2에서 2번 잡혔으니 규칙이 아예 막는 것은 아니다. 서는 각도·거리에 따라 들어가기도 하고 안 들어가기도 하는, 아슬아슬한 기준으로 본다(추정).

9-2에서 본 것 (2026-10-23, main 29f84ea, 1280x720, 12.7 fps, 카운트는 `/events`):

- 다수결로 깜빡임은 크게 줄었다. 한팔들기 37 → 5, 만세 16 → 3. 기준 4 충족.
- 만세가 실제 6회보다 적은 3회다. 이벤트는 #1 만세 2번, #4 만세 1번이었다. 정면·측면을 카운트로 나눌 수 없지만, 옆모습에서는 반대쪽 어깨가 가려져 어깨가 안 보이면 판정 자체를 하지 않는(`body()`가 None) 원문 규칙이라 측면 만세가 빠졌을 가능성이 크다(추정). 원문 9-2 "남는 한계"에 적힌 그대로다.
- 손 흔들기는 한 번도 `WAVE`가 안 됐다(기준 5 미통과). 원인은 7번.
- 메모리: tegrastats RAM 최대 raw 4797MB, smooth 4798MB, smooth 끝난 뒤 available 3.7GB.
- 종료 문제: SIGINT 한 번으로 안 끝났다. uvicorn이 브라우저 `/stream` 연결을 기다리며 "Waiting for connections to close"에서 멈춰 두 번째 SIGINT가 필요했다. raw 때는 끝나면서 `terminate called without an active exception … Aborted (core dumped)`가 나왔다(촬영·검출 스레드가 도는 중에 파이썬이 내려가서). 고친 것은 7번.

## 7. 미통과 기록과 다음 시도

### 9-2 1차 (2026-10-23): 기준 5 미통과 — 손 흔들기 0/3

1차 기록(6번)은 그대로 둔다. 아래는 2차를 하기 **전에** 적는다. 기준(3번 중 2번)은 바꾸지 않는다.

**`WAVE`가 되는 조건 (원문 코드 그대로):** 다수결 라벨이 "한팔들기"이고, 최근 1.5초 동안 올린 손목의 x 좌표(어깨 중심 기준, 어깨 너비 단위)가 8개 이상 있고, 그 x가 0.15 이상 움직일 때마다 방향을 보는데 그 방향이 **2번 이상** 바뀌어야 한다.

이 중 무엇에 걸렸는지 1차 화면만으로는 알 수 없다. 후보는 셋이다.
