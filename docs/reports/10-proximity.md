## 0. 이 단계에서 무엇을 하나

강의실의 **특정 물체(타겟, 예: 소화기)** 에 사람이 다가가는지 카메라 2대로 보고, 정해 둔 거리(근접 1.0m, 이탈 3.0m)를 넘으면 알람을 울린다.

왜 카메라가 2대일까? 카메라 1대는 "어느 방향에 사람이 있는지"만 알고 "얼마나 먼지"는 모른다. 그래서 1대로는 **발목이 바닥(높이 0)에 닿아 있다**고 가정해 거리를 구하는데, 교실에서는 책상에 발이 가려진다. 카메라 2대가 같은 어깨를 서로 다른 방향에서 보면, 두 시선이 만나는 점이 어깨의 3D 위치다(**삼각측량**). 어깨는 책상 위로 보이니 앉아 있어도 위치를 잡는다.

| 역할 | 무엇으로 |
| --- | --- |
| 타겟 찾기 | YOLOE가 문구("red fire extinguisher")로 후보 박스 → **EmbeddingGemma 2**가 크롭과 문구를 비교해 제일 맞는 것 하나 → 두 카메라로 삼각측량 |
| 사람 위치 | YOLO11n-pose의 어깨 중심(없으면 코) → 두 카메라 삼각측량 → 바닥 위 (x, y)와 높이 |
| 같은 사람 맞추기 | 얼굴·외모 안 씀. 두 카메라 점을 짝지었을 때 **재투영 오차**가 작은 쌍끼리 |
| 접근 판단 | 최근 1초 거리 변화로 접근/이탈, 경계에서 깜빡이지 않게 0.2m 여유(히스테리시스) |

진행 순서는 원문 그대로 **보정 → 문제 확인 → 개선 → 보완 → 알람 → 비교 → (이동 타겟)** 이다.

| 순서 | 무엇을 | 왜 |
| --- | --- | --- |
| 10-1 렌즈 보정 | 카메라마다 체커보드를 비춰 20장 자동 수집 → 렌즈 휨(K, 왜곡) 계산 | 웹캠 가장자리가 휘어 있어 그대로 계산하면 위치가 틀어진다 |
| 10-2 위치 보정 | 바닥·책상·벽에 기준점 8개 이상 테이프 → 줄자로 좌표 → 웹에서 두 카메라 사진 위를 클릭 | 각 카메라가 교실 어디에서 어느 방향을 보는지 계산(solvePnP) |
| 10-3 문제 확인 (`ankle1`) | 카메라 1대 + 발목 | 앉거나 책상 뒤에 서면 사람이 사라지거나 튀는 걸 직접 본다 |
| 10-4 개선 (`stereo`) | 2대 + 어깨 삼각측량 | 앉아도 위치가 유지되는지. 대신 한쪽에서 가리면 사라진다 |
| 10-5 보완 (`fused`) | 짝 없는 사람은 "어깨 1.2m"로 가정해 1대로 추정 | 추적은 안 끊기지만 오차가 큰 걸 확인 |
| 10-6 알람 (`--target`) | 문구로 타겟 자동 찾기 + 시나리오 5개 × 3회 | 실제 알람이 기대대로 울리는지 |
| 10-7 비교 | 같은 테이프 지점에서 세 방식 거리, fps·시간 차·RAM 표 | 세 방식의 장단점을 숫자로 |
| 10-8 이동 타겟 (`--moving`) | 카트를 밀어 다가가게 → 칼만 필터 + 충돌 예상 시간(TTC) | 거리보다 먼저 "부딪힐 것 같다"를 알리는지 |

## 1. 성공 기준 (실행 전에 적어 둔다)

원문 10단계에는 "성공 기준" 표가 따로 없다. 그래서 9단계처럼 원문 표의 **목표값**과 **빈칸 없이 채우기**를 기준으로 하고, 원문에 숫자가 없는 곳만 "우리 기준"을 실행 전에 정한다. 결과를 본 뒤 바꾸지 않는다. (아래 "우리 기준" 3개는 재웅 확인 전 제안이다. 8번 참고)

| # | 기준 | 근거 |
| --- | --- | --- |
| 1 | 10-1: 두 카메라 RMS **0.5px 이하** (1.0 이상이면 다시 촬영, 0.5~1.0은 "보통"으로 적음) | 10-1 3번 |
| 2 | 10-2: 평균 재투영 오차 카메라별 **3px 이하**, 계산 위치 vs 실측 **20cm 이내**, 검증점 C1·C2 3D 오차 **10cm 이내** | 10-2 표 "목표" |
| 3 | `ankle1`·`stereo`·`fused` 세 모드가 모두 켜지고 브라우저에서 평면도·사람 표가 보인다 | 10-3 ~ 10-5 |
| 4 | `stereo`·`fused`에서 화면의 **카메라 시간 차 80ms 이하** | 10-4 2번 |
| 5 | 10-7 두 표(7줄 × 3모드 거리, 3모드 fps·시간 차·RAM)를 빈칸 없이 채운다. 사라지면 "없음" | 10-7 |

| 7 | 10-6: "타겟 찾음" 좌표가 줄자 실측과 **30cm 이내** (우리 기준) | 10-6 1번 (원문 숫자 없음. 10-2 목표 20cm + 박스 중심 오차 여유) |

| 9 | 10-8 표 4줄을 채운다. "보통(1m/s)"·"빠르게(1.5m/s)"에서 충돌 위험 알람이 근접 알람보다 **먼저** 울린다 (우리 기준, "천천히"는 원문대로 안 울려도 됨) | 10-8 표·확인 포인트 |

- 미통과면 1차 기록은 그대로 두고, 원인과 바꿀 것을 먼저 적은 뒤 2차를 한다. 원문이 바꿔 보라고 한 손잡이만 쓴다: 보정은 "다시 촬영 / 클릭 다시 / 좌표 다시 재기", 알람은 `--near`·`--far`·`margin=0.2`·`v_th=0.3`, 매칭은 `max_err=15`, 이동 타겟은 `Kalman2D(q=...)`·`--ttc`, 타겟 문구에 색 넣기("cart with yellow tape"), 카메라 문제는 Q14(다른 USB 포트). 바꿨으면 값과 이유를 적는다.
- 카메라가 조금이라도 움직이면 10-2부터 다시 한다(원문). 실습 날 시작할 때마다 10-2 화면에서 **계산**만 다시 눌러 검증점 오차를 확인한다.

**8단계 `KEEP_MARGIN 0.03` 규칙은 쓰지 않는다.** 10-6은 YOLOE 후보 중 EmbeddingGemma 점수 1등을 고르는 방식이라 8단계 relabel과 구조가 다르다. 원문 코드를 바꾸면 "결과를 보고 바꾼 것"이 되므로, 타겟을 잘못 고르면 그때 원문 손잡이(문구에 색 넣기, 다시 찾기)부터 쓴다. 8단계 교훈은 "비슷한 물체가 화면에 여럿이면 틀리기 쉽다" → 타겟 근처에 비슷한 물체를 두지 않는 것으로 반영한다.
